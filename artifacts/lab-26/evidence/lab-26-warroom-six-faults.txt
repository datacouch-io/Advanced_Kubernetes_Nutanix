┌────────────────────────┬──────────────────┬─────────┬─────────────────┬─────────┬────────┬───────────────────────┬───────┬───────────┬────────────┬───────────┬────────────┬────────────────────┬────────┬──────────────────────────┬───────────────────┐
│        ENDPOINT        │        ID        │ VERSION │ STORAGE VERSION │ DB SIZE │ IN USE │ PERCENTAGE NOT IN USE │ QUOTA │ IS LEADER │ IS LEARNER │ RAFT TERM │ RAFT INDEX │ RAFT APPLIED INDEX │ ERRORS │ DOWNGRADE TARGET VERSION │ DOWNGRADE ENABLED │

│ https://127.0.0.1:2379 │ 4e3c161948c74816 │   3.7.0 │           3.7.0 │  8.7 MB │ 7.8 MB │                   11% │ 17 MB │      true │      false │         3 │       3274 │               3274 │        │                          │             false │

Diagnosis: the backend quota has been set to 16.7 MB (someone's tuning experiment
left in place) and the database is over half of it, with dead space accumulating
from deleted objects. Under sustained write load this reaches the NOSPACE alarm and
etcd goes read-only — at which point NOTHING else in this list can be fixed.

Remediation — compact to the current revision, then defragment:
  etcdctl compact <revision>
  etcdctl defrag
Measured on this cluster earlier in the run:
  before : dbSize 5.8 MB | inUse 2.8 MB | 53% not in use
  after  : dbSize 1.4 MB | inUse 1.4 MB |  1% not in use   (defrag took 16.5ms)

Diagnosis: the CR carries finance.shop.io/archive-before-delete but no controller

finalizer — after establishing that the archive it promises is genuinely not needed.

================ FAULT 5 — COREDNS / NETWORKPOLICY (Module 4) ================
$ kubectl -n shop exec shopper -- curl http://catalog        # by NAME
command terminated with exit code 6
$ kubectl -n shop exec shopper -- curl http://10.96.9.21   # by IP
  http=200

Diagnosis: the name fails and the IP works, so this is resolution, not reachability.
$ kubectl -n shop get networkpolicy shopper-egress -o yaml
  policyTypes=["Egress"] egressRules=[{"ports":[{"port":80,"protocol":"TCP"}],"to":[{"podSelector":{"matchLabels":{"app":"catalog"}}}]}]

  The egress rule allows the catalog and nothing else. An egress NetworkPolicy is
  default-deny once it selects a Pod, so UDP/53 to kube-dns is denied with it.

$ kubectl get clusterqueue nightly-batch -o jsonpath='{.spec.resourceGroups[0].flavors[0].resources}'
[{"name":"cpu","nominalQuota":"1"},{"name":"memory","nominalQuota":"1Gi"}]

Diagnosis: the Job asks for 2 CPU x 2 pods = 4; the ClusterQueue's nominal quota is 1.
The Job is not failing — it is Suspended, waiting for capacity that will never arrive
at this quota. 'kubectl get pods' shows nothing, which is why teams miss it.
