### 7. Schedules, TTL and expiry
$ velero schedule create orders-daily --schedule='0 2 * * *' --include-namespaces orders --ttl 72h
NAME           STATUS    CREATED                         SCHEDULE    BACKUP TTL   LAST BACKUP   SELECTOR   PAUSED
orders-daily   Enabled   2026-09-25 19:11:16 +0530 IST   0 2 * * *   72h0m0s      n/a           <none>     false

$ kubectl -n velero get backup <name> -o jsonpath='{.spec.ttl} {.status.expiration}'
ttl        = 720h0m0s
completed  = 2026-09-25T13:42:26Z
expiration = 2026-10-25T13:42:26Z

-> TTL is set at backup creation and stamped onto the object as an absolute
   expiration. Velero's gc-controller deletes the backup AND its data when that
   time passes. Changing a Schedule's --ttl does not re-date backups already taken.
