=== 1.4  Disruption #1: delete a Pod -> ReplicaSet recreates it ===

$ kubectl get pods -l app=web           # a few seconds later

web-69c6f74b8b-9g4pc   1/1   Running   0   2m25s

=== 1.5  Disruption #2: level-triggered proof ===

$ RS=web-69c6f74b8b
$ kubectl scale rs "$RS" --replicas=1
replicaset.apps/web-69c6f74b8b scaled
$ kubectl get rs "$RS" -o jsonpath='rs.spec.replicas={.spec.replicas}'   # read back immediately
rs.spec.replicas=3
# The Deployment controller reverted the hand-edit faster than the next GET could observe the "1".

$ kubectl delete rs "$RS"
replicaset.apps "web-69c6f74b8b" deleted from default namespace
$ kubectl get rs -l app=web    # a few seconds later
NAME             DESIRED   CURRENT   READY   AGE
web-69c6f74b8b   3         3         3       4s
# Rebuilt with the identical name (name = hash of the unchanged Pod template) + 3 fresh Pods (AGE 4s).

=== 1.8  Spec change convergence ===

$ kubectl scale deployment web --replicas=6
deployment.apps/web scaled
immediately after:  gen=3  observedGen=3  status.replicas=6  ready=5
after convergence:  gen=3  observedGen=3  status.replicas=6  ready=6
# generation/observedGeneration bump together (controller ACKed the new spec instantly);
# readyReplicas lagged by exactly the one new Pod (5 -> 6) -- that is the real convergence signal.
