=== 4.2  Allocatable < capacity ===
$ kubectl get nodes -o custom-columns='NODE,CPU_ALLOC,CPU_CAP,MEM_ALLOC'

# The scheduler fits Pods into ALLOCATABLE (940m), not capacity (2 vCPU).

=== 4.3  Pending #1: insufficient cpu (Pod requests 5 cores) ===
$ kubectl describe pod -l app=hog  (Events)
Warning  FailedScheduling  default-scheduler  0/2 nodes are available: 2 Insufficient cpu.
                                              preemption: 0/2 nodes ... Preemption is not helpful.
Normal   NotTriggerScaleUp cluster-autoscaler Pod didn't trigger scale-up
# (autoscaling not enabled on this cluster -> stays Pending. With --enable-autoscaling it would add a node.)
FIX: kubectl set resources deployment hog --requests=cpu=100m  -> Running

=== 4.4  Pending #2: node affinity/selector (nodeSelector disktype=ssd) ===
Warning  FailedScheduling  default-scheduler  0/2 nodes are available: 2 node(s) didn't match Pod's node affinity/selector.
FIX: kubectl label node <NODE> disktype=ssd  -> the pending Pod schedules onto it

=== 4.5  Pending #3: untolerated taint (dedicated=analytics:NoSchedule on all nodes) ===
Warning  FailedScheduling  default-scheduler  0/2 nodes are available: 2 node(s) had untolerated taint(s).
FIX: patch a toleration (key=dedicated, value=analytics, effect=NoSchedule)  -> Running (verified)
     (or remove the taint: kubectl taint nodes --all dedicated=analytics:NoSchedule- )

=== 4.6  Pending #4: unbound PVC (storageClassName: does-not-exist) ===
$ kubectl get pvc data
data   Pending   does-not-exist
Warning  FailedScheduling  default-scheduler  0/2 nodes are available: pod has unbound immediate PersistentVolumeClaims.
FIX: recreate PVC with storageClassName: standard-rwo (GKE default, pd.csi.storage.gke.io)  -> Bound -> Pod Running
