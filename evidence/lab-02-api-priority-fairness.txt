=== 2.4  Custom restricted lane + classification + seat allocation ===

$ kubectl apply -f (restricted-storm PriorityLevelConfiguration, NCS=1, Reject) + (storm-user-fs FlowSchema)
prioritylevelconfiguration.flowcontrol.apiserver.k8s.io/restricted-storm created
flowschema.flowcontrol.apiserver.k8s.io/storm-user-fs created
$ kubectl create clusterrolebinding storm-user-view --clusterrole=view --user=storm-user
clusterrolebinding.rbac.authorization.k8s.io/storm-user-view created

# storm-user classifies into -> restricted-storm

$ kubectl get --raw /metrics | grep nominal_limit_seats | grep -E 'restricted-storm|global-default|workload-low'
apiserver_flowcontrol_nominal_limit_seats{priority_level="global-default"} 49
apiserver_flowcontrol_nominal_limit_seats{priority_level="restricted-storm"} 3
apiserver_flowcontrol_nominal_limit_seats{priority_level="workload-low"} 244
# Seats are proportional to shares: NCS=1 -> only 3 seats.

=== 2.5  Storm test: critical traffic survives ===

# 60 concurrent LISTs as storm-user (raw HTTP status via kubectl proxy + curl):
storm status distribution (storm-user):
  43 200
  17 429
# a critical admin request in the same window:
critical admin GET /api/v1/namespaces -> 200

$ kubectl get --raw /metrics | grep rejected_requests_total | grep restricted-storm
apiserver_flowcontrol_rejected_requests_total{...,priority_level="restricted-storm",reason="concurrency-limit"} 68
apiserver_flowcontrol_rejected_requests_total{...,priority_level="restricted-storm",reason="queue-full"} 17
# The noisy client is throttled inside its own 3-seat lane; admin traffic in another lane is untouched.

GOTCHA 1: kubectl retries 429s client-side (client-go backoff), so a `kubectl get --as=storm-user`
loop shows almost no 429s -- requests just get slow. Use raw curl or the rejected_requests_total metric.
GOTCHA 2: `wait` with no args also waits on the backgrounded `kubectl proxy` (never exits) -- capture the
curl PIDs and `wait "${pids[@]}"`.
